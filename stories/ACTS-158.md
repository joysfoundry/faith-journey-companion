## Goal
As someone sharing the Oravia beta link, I want the link preview to show the Oravia
mark, a one-line description, and that it is a free beta needing no account, so that
recipients know what they are opening before they tap.

## Context
Nothing in the app sets `og:image`. `__root.tsx` sets title/description/theme-color
only, and the per-route heads (`index`, `about`, `pray`, …) add `og:title` /
`og:description` but never an image, `og:url`, `og:site_name`, or any `twitter:*` tag.

With no image to find, Apple falls back to **screenshotting the page** — and what it
catches is the beta gate's name prompt, rendered far too small to read. Confirmed from
a real iMessage share of `myoravia.lovable.app` (JC, 2026-09-05).

## Acceptance criteria
- [x] A 1200×630 share card at `public/og-cover.png` — the ACTS-148 cross-in-compass
      mark, the name, the tagline "Your devotional life, gathered.", one line of about
      copy, and a "Free beta · No account needed" line, in the brand palette
      (Marian blue ground, ivory, antique gold).
- [x] Generated by a committed `docs/brand/make_og.py` following the
      `make_about.py` / `make_flyer.py` convention, so copy edits are re-runnable.
- [x] `__root.tsx` gains `og:image` (**absolute** URL), `og:image:width`/`height`/`alt`,
      `og:type`, `og:site_name`, `og:url`, and `twitter:card=summary_large_image`
      + twitter title/description/image — so **every** route inherits a card.
- [x] Per-route heads still override title/description without dropping the image.
- [x] Verified: the served `<head>` carries the tags and the image URL returns 200.

## Decisions
- **Absolute URL from env.** Scrapers will not resolve a relative `og:image`. Read the
  origin from `VITE_PUBLIC_URL`, falling back to `https://myoravia.lovable.app`,
  so preview deploys are not pinned to prod.
- **The beta gate does not block scrapers.** The passcode gate is client-side, so the
  `<head>` is served to crawlers regardless. The card is therefore visible to anyone
  holding the link even though the app is not — accepted, it is an invite card.

- **No call-to-action on the card. Closed by JC 2026-09-05** — "no need for a way to
  continue, it works as it is." The whole preview is tappable, so a button would be
  decoration; the card names the app and the URL and stops there.
- **`oravia-about.png` was never published as an artifact.** It is a repo file that gets
  sent as an image, so stale copies circulate with no canonical version to correct —
  the only fix for an old one is to re-send the regenerated file. Checked against the
  account's artifacts: the ivory About card is not among them.

## Verified (2026-09-05)
Dev server, reading the **server-rendered** HTML (what a scraper sees — fetched, not
hydrated):
- `/`, `/about`, `/pray`, `/settings` each carry `og:image`, `og:image:*`,
  `twitter:card`/`title`/`description`/`image`, `og:url`, `og:site_name` — while
  keeping their **own** `<title>` and `og:title`. Confirms the merge assumption: the
  child heads override by key and leave the image tags alone.
- `/og-cover.png?v=1` → **200**, `image/png`, 102 KB (every platform's cap is ≥ 5 MB).
- App still renders (beta gate paints, zero console errors) — the `process` guard below
  is load-bearing, see Gotchas.
- `tsc --noEmit` clean, `eslint src/routes/__root.tsx` clean, `vite build` clean.

## Gotchas
- ⚠️ **`process` is not defined in the browser.** The first cut copied
  `integrations/supabase/client.ts`'s `import.meta.env[...] || process.env[...]` pattern
  verbatim. That file gets away with it because its `VITE_*` value is always set, so the
  `process` arm never evaluates client-side. Here `VITE_PUBLIC_URL` is normally **unset**,
  making that arm the *usual* path — and `head()` runs on every client navigation, so
  unguarded it would throw in the **root route** and blank the whole app. Now behind
  `typeof process !== "undefined"`.
- **Scrapers cache hard.** iMessage/Facebook/Slack will keep serving the old preview for
  an already-shared URL. Hence `?v=1` on the image — bump it whenever the card is
  redrawn. A first re-share after deploy may still need a cache-busting query string.
- **The card is public even though the app is not.** The beta gate is client-side, so
  crawlers get the `<head>` regardless. Accepted — it is an invite card.
